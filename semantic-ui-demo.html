Semantic UI vs. Video-Streamed UI

Both panels show the same cloud-gaming video stream, degraded identically by the Network quality slider. Left: the UI is baked into the video pixels (traditional). Right: the server sends UI state as JSON over a real WebRTC data channel, and the client renders it locally as crisp DOM/SVG on top of the video. Drag quality down and watch the left HUD dissolve while the right HUD stays sharp.

① Traditional — UI baked into the video

HUD is part of the encoded pixels → degrades with the stream.

② Semantic UI — rendered locally from the data channel

Video carries only the game world; HUD is drawn client-side from metadata.

Why this is convincing: the right-hand HUD is built only from JSON that arrives on the RTCDataChannel (ui-metadata) — it never touches the video codec, so resolution loss and compression blur cannot affect it. Notice the UI metadata costs a tiny fraction of the video bitrate, yet stays perfectly legible at network levels where the baked-in UI is unreadable.
